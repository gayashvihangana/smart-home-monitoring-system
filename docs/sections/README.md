# Report sections

The technical report is written one section per author, then assembled by Member
C into `docs/technical-report.md`.

Writing in separate files rather than straight into one document is deliberate:
three people editing a single markdown file at once is the most likely merge
conflict left in this project, and it would land on the deadline.

| File | Section | Author | Target |
|---|---|---|---|
| `01-introduction.md` | Introduction, system overview, architecture diagram | C | ~400 words |
| `02-synchronising-mechanism.md` | The synchronising mechanism | B | ~800 words |
| `03-floor-representation.md` | Floor representation | A | ~600 words |
| `04-simulator-operations.md` | Simulator operations | C | ~600 words |
| `05-contributions.md` | Individual contributions and limitations | C | ~250 words |

## Rules

- **Edit only your own file.** Anything else, agree in the group chat first.
- Each section is defended by its author in the viva, so write what you can
  explain without notes.
- State limitations explicitly. Markers reward acknowledged limitations and
  punish discovered ones.
- Member C edits the assembled report for one consistent voice — expect your
  wording to be adjusted, not your content.

## Deadline

Sections due to Member C by **noon on Monday 17 August**. Submission is 23:59 the
same day, and the assembly, editing and final read need the afternoon.
